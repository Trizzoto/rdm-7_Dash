# CAN Keypad Market Research — July 2026

> Research input for the RDM platform plan (`docs/PLATFORM_PLAN_2026-07.md`).
> Compiled 2026-07-10 from vendor documentation, distributor pricing, and forum threads.

## 1. Blink Marine — the de-facto OEM of the aftermarket

**Product line.** Blink's motorsport-relevant line is the **PowerKey Pro** series ([series page](https://blinkmarine.com/series/powerkey-pro/)). Naming encodes the grid: **PKP-2200-SI** (2×2, 4 keys), **PKP-2300-SI** (2×3, 6), **PKP-2400-SI** (2×4, 8), **PKP-2500-SI** (2×5, 10), **PKP-2600-SI** (2×6, 12), **PKP-3500-SI** (3×5, 15), **PKP-1600-SI** (1×6), plus **-LI** variants with large 24 mm keys (PKP-1100/1200/1500-LI) and the **PKP-3500-SI-MT/MTR/MTP** (13 keys + 2 rotary encoders, [announcement](https://blinkmarine.com/introducing-pkp-3500-si-mt-can-bus-keypad-with-rotary-encoders/)). All are IP67, UV-stable, with **removable laser-etched icon inserts** (15 mm) chosen via an online insert configurator, RGB **status LED rings in 9 colors** (red, green, blue, yellow, cyan, purple, "white ice", amber, lime) plus matching key backlight. Older **PowerKey 1000/1400** and the budget **PWTR4/PWTR6** round out the range ([products](https://blinkmarine.com/products/)).

**Protocols.** Every PKP speaks **CANopen (DS-401 device profile) and SAE J1939, switchable in the field without reflashing** — the switch is done by CAN command, not DIP switches ([PKP-SI datasheet](https://www.in-carpc.co.uk/wp-content/uploads/2022/11/DOC_BlinkKeypad_Datasheet_PKP-SI_Series.pdf)). CANopen conventions: **default node-ID 0x15**, so button states go out on **TPDO1 = 0x195** (0x180+ID), LED/backlight commands come in on RPDOs (0x215/0x315…), SDO config at **0x615** (0x600+ID), heartbeat/bootup at **0x715**; factory baud 125 kbit (resellers re-program to 500 k/1 M). SDO objects handle config — e.g. **0x2010 = baud rate, 0x2013 = node-ID** on the PKP2300 ([ManualsLib](https://www.manualslib.com/manual/1577092/Blink-Marine-Pkp2300.html), [HPA CANopen keypad reference thread](https://www.hpacademy.com/forum/canbus-communications-decoded/show/canopen-keypad-reference-information/)). The keypad must be NMT-started by a master before it transmits. J1939 mode uses **Proprietary-A PGN 61184 (0xEF00)**, addressable, default destination 0xFF broadcast, 8-byte frames with unused bits 0xFF, and supports **Address Claim** so a spare keypad self-announces ([PKP2600SI J1939 UM](https://blinkmarine.com/app/uploads/2024/11/PKP_2600_SI_J1939_UM.pdf), [Murcal blog](https://www.murcal.com/blog/powerkey-pro-keypads-by-blink-marine)).

**Configuration.** There is **no consumer PC tool for the PKP line** (the KCS software is for their Keybox I/O module) — configuration happens over CAN, which is why every ECU vendor embeds keypad programming in their own suite (M-Tune, RaceStudio 3, PCLink/PDMLink). AiM even publishes a FAQ on re-addressing a Blink keypad from the PDM ([AiM FAQ PDF](https://www.aimsports.com/download/faqs/eng/hardware/configuring/pdms/FAQ_Configuring_Blink_Marine_keypad_101_eng.pdf)).

**Pricing/where bought.** Direct/US distribution: **PKP-2400-SI $280, PKP-2600-SI $350, PKP-3500-SI $425** ([HCR Innovations](https://hcrinnovations.com/shop/blink-marine-pkp-2400-si/)), **€318 ex-VAT** for the 3500 in EU ([XTRA Motorsport](https://xtramotorsport.com/product/blink-marine-pkp-3500-si-can-keypad-with-15-buttons/)). Racers buy from Murcal (US master distributor), shop.blinkmarine.com, HCR, XTRA, T7 Design (UK), Dubye Performance (AU, sells "Blink 10-button for MaxxECU/Link"), eBay (~$350) — or as ECU-vendor rebrands below.

## 2. How competitors integrate keypads

- **Haltech** — sells 8-button (2×4, HT-011501, ~**A$515**) and 15-button (3×5, HT-011502, **A$615–694**, discounted to A$440) keypads ([Haltech](https://www.haltech.com/product/ht-011502-haltech-can-keypad/), [Unwise](https://unwiseperformanceparts.com.au/products/ht-011502), [T.I. Performance](https://www.tiperformance.com.au/products/haltech-can-keypad-15-button-3x5/)). Per the [HPA MoTeC-vs-Haltech thread](https://www.hpacademy.com/forum/canbus-communications-decoded/show/motec-vs-haltech-15-button-keypad/), Haltech's and MoTeC's 15-button units are **rebranded Grayhill hardware** on CANopen with vendor-locked node-IDs (**Haltech 0x0C, MoTeC 0x0A**) and different PDO IDs. Config is in **NSP**: enable the keypad under "Haltech CAN System", assign each button **momentary or toggle**; each key has **3 LEDs — amber mirrors the actual function output state** (fan LED lights when the fan runs even if temperature triggered it), **red = error**; unassigned buttons don't light ([quick-start guide](https://justenginemanagement.com/wp-content/uploads/2020/11/HAL_KeyPad_QSGweb.pdf)). Multi-position switching requires a momentary-mode + "Max Position" workaround rather than a first-class multi-state mode ([Haltech forum](https://forums.haltech.com/viewtopic.php?t=35201)).
- **MoTeC** — 15-button #41400 ≈ **US$589** ([Real Street](https://www.realstreetperformance.com/motec-15-position-can-keypad-m-keypad-15.html)). Buttons momentary/toggle, or **two keys paired as up/down multi-position**; 3 LEDs per key individually programmable; up to **4 keypads on one bus** (factory config needed) ([MoTeC](https://www.motec.com.au/products/15%20Button%20Keypad?catId=14)). Notably MoTeC's PDM software **lets you re-address TPDO IDs, so it can consume most third-party CANopen keypads** — the most interop-friendly of the bunch ([HPA thread](https://www.hpacademy.com/forum/canbus-communications-decoded/show/canopen-keypad-reference-information/)).
- **ECUMaster** — sells rebadged Blink "CAN Keyboards" (4/6/8/12/15; 12-button **US$399** [ECUMaster USA](https://ecumasterusa.com/products/12-position-can-keyboard)) plus the **CAN Switch Board V3** (25×25 mm, 8 switch + 8 analog inputs + 4 LED outputs, for steering wheels) ([manual](https://www.ecumaster.com/files/devices/switchboard/switchboardManual.pdf)). All keypads ship at **node 0x15** — running two requires manually re-addressing one to 0x16 via their **Light Client** tool. PMU16 keypad config is wizard-ish ([guide](https://ecumasterusa.com/pages/streamlined-control-configure-can-keypads-with-ecumaster-pmu16)), but the switchboard needed hand-built CAN frames: a user gave the exact frame ("0x643 00 00 01 00") and said *"I can't find how to configure a switchboard output"*, resolved only when told to *"create a function to build a canbus message"* ([HPA thread](https://www.hpacademy.com/forum/pdm-installation-and-configuration/show/ecumaster-switchboard-configuration/)).
- **Link ECU** — rebadged Blink keypads (12-button 101-0239 **is** a PKP-2600-SI, [rad-industries](https://rad-industries.com/pn-101-0239-link-ecu-link-can-keypad-12-button/)); priced **US$469–736** across dealers (8-button 101-0237 $678.50 at one) — a huge markup spread over the $350 Blink original. Config via **PCLink/PDMLink**: keypad functions on the Razor PDM map to ECU "CAN DI" inputs, with a Quick Setup dialog ([KB](https://kb.linkecu.com/pdm-kb/latest/can-setup)). Pain: a user asked to make an **LED follow ECU status rather than just local press** — *"tried to allocate the PDM's CAN function without success"* ([forum](https://forums.linkecu.com/topic/17596-about-keypad-settings/)); Link later shipped "LED feedback dependent on a parameter" in a PDM firmware update ([changelog](https://linkecu.com/pdmlink/PDM_Changelog_R6.pdf)). Other threads: ["Trouble getting Blink Marine CAN Keypad set up"](https://forums.linkecu.com/topic/26191-trouble-getting-blink-marine-can-keypad-set-up/) (generic Blink at 125 k/0x15 vs Link's pre-programmed 1 Mbit expectations), and multi-PDM/keypad ID clashes ([2×PDM + keypad](https://forums.linkecu.com/topic/30923-2x-razor-pdm-1x-blink-marine-keypad-issue/)).
- **AiM** — K8/K15 keypads (K8 **US$299**, [BimmerWorld](https://www.bimmerworld.com/Gauges-Data-Acquisition/Data_Gauge_Accessories/AiM-K8-8-Button-CAN-Bus-Keypad-2m-Expansion-Cable.html)) for PDM08/32, configured in **RaceStudio 3**: per-button **Momentary / Toggle / Multistatus (0..max)**, **short-vs-long-press time thresholds**, LED per-state color with **solid/slow/fast blink**, max 8 keypads per master at node 0x15–0x1C ([AiM keypad user guide](https://www.aim-sportline.com/download/doc/eng/k_keypads/K_Keypads_eng.pdf)). But RS3 **only supports the Blink 8/12-button profile**: *"Still not sure how you will support anything other than the Blink Marine 8 and 12 button keypads"* ([HPA](https://www.hpacademy.com/forum/canbus-communications-decoded/show/motec-vs-haltech-15-button-keypad/)).
- **Holley/Racepak** — SmartWire PDM + 8-key keypad (500-KT-KPAD8), programmed over USB. Structural pain: **V-Net↔Holley CAN is one-way fixed data** — *"fuel pump or fan status cannot be sent from the ECU to the PDM… you can't have keypad buttons turn on launch control or activate NOS"* ([Holley forums](https://forums.holley.com/forum/racepak/racepak-smartwire/33314-holley-dominator-racepak-smartwire-questions), [SmartWire manual](https://documents.holley.com/techlibrary_smartwire_installation_manual.pdf)).
- **Emtron** — own 8-button CAN keypad, config in **Emtune**; each button independently **toggle through 8-position binary**, 3 RGB LEDs per key ([Emtune help](https://help.emtronaustralia.com.au/emtune/EmKeypad8.html), [manual](https://downloads.emtronaustralia.com.au/files/7_CAN%20Devices/1_Manuals/Emtron%208%20Button%20CAN%20Keypad.pdf)).
- **MaxxECU** — best-documented DIY story: supports Blink RACEPAD/CAN-PRO/4–15-key over **J1939** (pre-programmed if bought from them). M-Tune exposes protocol, baud, CANopen ID, **backlight color, LED brightness 0–63 with separate lights-on/lights-off levels**, per-state colors, red-blink fault, buttons as momentary or **2–6-position states** feeding DI functions ([keypad settings](https://www.maxxecu.com/webhelp/settings-can_keypad-keypad_settings.html)). Their conversion procedure shows the friction everyone hits: disconnect PDM, match 125 k, write J1939, step to 250 k, reprogram to 500 k, restart ECU after every change — *"Don't forget to restart the MaxxECU after each CAN bus baudrate change"* repeated verbatim ([setup guide](https://www.maxxecu.com/webhelp/settings-can_keypad_setup.html)).

## 3. What buttons actually do, and the PDM question

Typical mappings: **pit limiter, launch/anti-lag arm, start/ignition, thermofan override, fuel & water pumps, headlights/rain light, wiper sequences, blinkers, boost/traction/map select, fuel-reset to ECU, logging marker**. A GT3/endurance build runs 12–16 switched circuits ([HPA "What is a PDM"](https://www.hpacademy.com/technical-articles/what-is-a-pdm-and-why-do-you-need-one/)). Keypads usually pair with a PDM (Razor, PMU16, PDM32) as the output stage — but **keypad-without-PDM is a real, supported pattern**: Haltech Elite/Nexus, MaxxECU and Emtron all consume keypads directly as ECU virtual inputs (map switching, limiters, logging), and Link maps keypad functions to CAN DIs with or without a PDM. RDM-7's equivalent — keypad → dash channel → displayed state + re-broadcast CAN frame → ECU or CAN output expander — matches an established pattern, not a novelty.

## 5. Implications for RDM's keypad configurator

1. **Auto-discovery beats manuals.** The #1 forum failure mode is baud/node/protocol mismatch. Sniff the bus for CANopen bootup/heartbeat (0x700+ID) and J1939 address claims, identify keypad model/protocol/baud, and offer one-click adoption — nobody does this well; MaxxECU's multi-restart dance is the state of the art.
2. **In-app reprogramming** (SDO 0x2010/0x2013-style baud/node writes, protocol switch, collision fix when two keypads both sit at 0x15) with a guided wizard, plus **presets for already-programmed vendor keypads** (Haltech 0x0C, MoTeC 0x0A, Blink/Link/AiM/ECUMaster 0x15 @1M/500k/125k) so users can reuse hardware they own.
3. **Full button-mode model**: momentary, toggle, n-position multi-state (2–6+), paired up/down keys, and short/long-press thresholds (AiM's differentiator).
4. **LED = channel-driven state, not local echo.** Haltech's "amber follows the real output" is the loved behavior; Link users begged for it. In RDM terms: bind each key's LED to any channel with per-state color (9 colors), solid/slow/fast blink, and fault-red — reusing the existing widget-rules engine is a natural fit.
5. **Brightness & night mode**: global LED brightness 0–63 plus backlight color, with **day/night pairs tied to RDM's existing night_mode** — matches MaxxECU's lights-on/off levels and beats everyone on integration.
6. **Visual, live keypad preview** in the designer (render the grid, icon inserts, simulated presses, live LED state from the dash) — no competitor offers WYSIWYG keypad config; it plays directly to a "Visual Designer" brand.
7. **Function templates** (pit limiter, launch arm, fan override, pump, map switch) and a clean keypad→dash→CAN-out path so a keypad is useful without a PDM, plus forwarding profiles for popular PDMs later.
