### A2. Expander vs PDM — where the line is, and the gap

The line: **expanders** carry sensor inputs plus signal-level outputs (0.5–8 A low-side/half-bridge, driving LEDs, small solenoids); **PDMs/PMUs** carry 15–25 A protected high-side outputs with digital fusing and cost US$1,100–2,000 (PMU16 US$1,499; Haltech PD16 in the same bracket). Club racers typically buy a PDM only when rewiring a whole car; when adding sensors to an existing dash/logger they buy an expander — and today that means either a weak cheap box (Haltech IO12: no TC, 1 A outputs, Haltech-only) or a pro box (E888 US$945, still no real power outputs; add a TC8 at US$629 if the dash has no TC option). **The gap is real and documented**: Link's own forum wishlist has users asking for exactly a "CAN IO expander with built-in EGT amplifier, 4 analogue and 4 digital inputs" ([forums.linkecu.com](https://forums.linkecu.com/topic/21511-can-io-expander/)), and AEM's US$361/22-channel unit shows the price point is feasible — but AEM locked it to CD dashes only. Nothing under ~US$500 combines analog + thermocouple + a handful of 2–10 A outputs with **vendor-agnostic, user-configurable CAN**.

### A3. Config UX today

- **Haltech NSP**: Devices tab → tick-box to enable IO Box A/B, TCA, WBC ([support.haltech.com](https://support.haltech.com/portal/en/kb/articles/devices)); pins then appear as assignable IO in the Functions tab (pin → function → calibration). PD16 is deeply integrated: "any sensors, inputs or outputs wired into the PD16 are automatically and instantly available for ECU functions" ([haltech.com](https://www.haltech.com/news-events/new-release-pd16-power-distribution-reimagined/)).
- **ECUMaster**: pin → function → calibration in per-device clients; ADU/PMU import **CANX templates** or **DBC files** and export custom streams back to .CANX ([ADU manual via ManualsLib](https://www.manualslib.com/manual/1521241/Ecumaster-Adu-5.html?page=93), [community thread on DBC import](https://community.ecumaster.com/t/importing-a-dbc-file/870)).

## B. Multi-Product Suite Architecture

- **Haltech NSP (single app)** — one binary configures Elite/Nexus ECUs, iC-7 dashes, PD16, keypads, IO boxes. Their **multi-master CAN** update treats keypads/PD16 as *pools of IO elements* that ECU and dash claim individually; conflicts resolve to a user-defined safe state set by the first master on the bus ([support.haltech.com](https://support.haltech.com/portal/en/kb/articles/multi-master-can)). Sentiment is strongly positive on the destination ("Nexus… a dream to tune on with NSP", [HPA forum](https://www.hpacademy.com/forum/general-tuning-discussion/show/what-digital-dashes-work-well-with-motec-aem-aim/)) but the migration was rough (below).
- **AiM Race Studio 3 (single app)** — one app for all device types with a **Connected Devices list**; a blue badge appears next to any device with firmware available, and **updating a master unit cascades to its connected expansions** ([aim-sportline.com Web Updates](https://www.aim-sportline.com/docs/racestudio3/manual/html/web-updates.html)). Users call the software "a bit clunky" but the hardware great value ([Rennlist](https://rennlist.com/forums/racing-and-drivers-education-forum/778797-aim-vs-motec.html)).
- **MoTeC (split tools)** — ECU Manager + Dash Manager + PDM Manager + i2 analysis, plus paid feature unlocks. i2 Pro licenses are machine-locked with a US$100 transfer fee ([motec.com.au](https://www.motec.com.au/i2/i2licences/)), and prospective buyers cite "horror stories of… getting charged for things left right and center" ([HPA forum](https://www.hpacademy.com/forum/off-topic-discussion/show/if-i-wanted-to-buy-a-motec-what-extra-costs-are-there-or-adam-from-link-can-you-advise-on-my-questions-from-a-link-perspective/)). Pro-grade, but the multi-app + licensing model is the thing everyone else is positioned against.
- **ECUMaster (per-device clients, converging)** — separate ADU/PMU/EMU clients, now supplemented by **Light Client**: it *discovers compatible devices on the bus*, monitors/decodes CAN traffic, edits per-device properties, changes the bitrate of *all* devices on a bus in one click, and saves per-device-type project files (`.ltc-switchboard`, etc.) ([Light Client manual](https://www.ecumaster.com/files/LightClient/LightClientManual.pdf)) — a halfway house, since big devices still need their own clients.
- **Holley (single suite, version-locked)** — one EFI suite where PC software, ECU firmware and dash firmware "must all be version compatible" ([holley.com](https://www.holley.com/support/fuel_injection/hp_and_dominator_efi/)) — users must upgrade everything in lockstep, a known friction source.
- **Keypads** — Blink Marine PKP keypads speak CANopen/J1939 and are resold/integrated by ECUMaster, Link, Haltech and MaxxECU ([blinkmarine.com](https://blinkmarine.com/industries/motorsport/), [MaxxECU keypad setup](https://www.maxxecu.com/webhelp/settings-can_keypad.html)); every serious suite now configures keypad buttons as first-class IO.

### User pain points (with sources)

1. **NSP updater bugs/loops** — "Loading Framework Definition…" popup loops for over an hour, reinstall didn't fix ([Haltech forums](https://forums.haltech.com/viewtopic.php?t=35263)); ESP→NSP migration threw errors and required manual firmware staging ([Haltech forums](https://forums.haltech.com/viewtopic.php?t=35330), [RX7Club](https://www.rx7club.com/haltech-forum-62/haltech-elite-1500-firmware-update-nsp-1171984/)).
2. **RS3 config version lock-in** — configs converted by a new RS3 version are no longer readable by older versions ([AiM release notes](https://www.aim-sportline.com/docs/racestudio3/html/release/software-release.html)); plus "can't communicate with device" multi-device connection failures ([AiM FAQ](https://www.aimtechnologies.com/support/information/faq/race-studio-3/)).
3. **RS3 general clunkiness** — "software a bit clunky, but a great unit" is the recurring AiM verdict ([Rennlist](https://rennlist.com/forums/racing-and-drivers-education-forum/778797-aim-vs-motec.html)).
4. **MoTeC nickel-and-diming + tool sprawl** — machine-locked i2 Pro licenses, $100 transfer fee, paid unlocks per device ([HPA forum](https://www.hpacademy.com/forum/off-topic-discussion/show/if-i-wanted-to-buy-a-motec-what-extra-costs-are-there-or-adam-from-link-can-you-advise-on-my-questions-from-a-link-perspective/), [motec.com.au](https://www.motec.com.au/i2/i2licences/)).
5. **Vendor lock-in on expanders** — AEM's 22-ch module works *only* with CD dashes, "not compatible with… 3rd party ECUs or loggers" ([AEM](https://www.aemelectronics.com/products/ev_conversions/dashes/can_bus_expansion/parts/30-2212)); Haltech IO boxes have hard-coded IDs and a 2-unit cap ([Haltech](https://www.haltech.com/product/ht-059900-io-12-expander-12-channel/)).
6. **Missing product = pain** — Link users publicly requesting a CAN IO expander with EGT on the official wishlist ([Link forums](https://forums.linkecu.com/topic/21511-can-io-expander/)).
7. **Channel-count ceilings in cross-vendor CAN** — AiM's standard M1 template only receives 64 channels, silently dropping data ([HPA forum](https://www.hpacademy.com/forum/motec-m1-software-tutorial/show/what-digital-dashes-work-well-with-motec-aem-aim/)).
8. **Lockstep firmware pain (Holley)** — PC software/ECU/dash must be version-matched or things break ([Holley](https://www.holley.com/support/fuel_injection/hp_and_dominator_efi/)).

## Implications for RDM

**Suite architecture: one app, device-modular — the NSP/RS3 pattern, not the MoTeC split.** Concretely: (1) a **device tree pane** ("Devices on this car") populated by discovery — RDM already does WiFi subnet-sweep discovery and has a CAN bus on every product, mirroring ECUMaster Light Client's bus discovery; (2) **per-device tabs** inside one window sharing a **single car project file** that bundles dash layout + keypad map + IO expander config + lap timer settings (nobody except Haltech really nails cross-device sharing — RDM's existing `channels.json` registry is the natural spine: make channel names car-scoped so an IO-expander pin named `oil_press` is instantly bindable on the dash, keypad LED rules, and logger); (3) a **whole-network firmware manager** modeled on RS3's Connected Devices badge + cascade updates — with explicit compatibility checks to avoid Holley-style lockstep pain; (4) **CAN ID auto-assignment with conflict validation** at project level (Haltech's fixed Box A/B is the crude version; do it properly), plus **DBC import/export** like ECUMaster so RDM devices drop into MoTeC/Link/Haltech ecosystems — that's the trojan horse for selling the expander to non-RDM-dash owners. Keep configs offline-editable with device sync on connect (all leaders do this; RDM's current live-editing model should gain an offline project mode).

**IO expander sweet spot:** ~US$349–449 (AU$550–700), one box: **8× analog 0–5 V (12-bit+), 4× K-type thermocouple, 4× digital/frequency (incl. VR-capable ×2), 4× low-side PWM 2 A + 2–4× half-bridge/high-side 8–10 A outputs**, configurable 11/29-bit CAN at 125k–1M with an RDM-native protocol *and* generic DBC-exportable broadcast. That combination — TC + analog + usable power outputs + open CAN — does not exist under US$500 today: it beats Haltech IO12 (US$370, no TC, no power) on capability, undercuts E888+TC8 (~US$1,574 combined) by ~70%, and dodges AEM's fatal lock-in mistake. Ship the ECUMaster-style pin → function → calibration → CAN-broadcast wizard inside the suite and it doubles as the acquisition funnel for the dash.
